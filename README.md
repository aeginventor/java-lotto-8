# 🎰 우테코 프리코스 3주 차 과제: 로또

## 📌 프로젝트 개요
간단한 로또 발매기 프로그램입니다. 사용자는 구입 금액을 입력하여 로또를 구매하고, 당첨 번호와 보너스 번호를 입력하여 당첨 통계 및 수익률을 확인할 수 있습니다.

로또 번호는 1부터 45까지의 숫자 중 중복되지 않는 6개의 숫자로 구성되며, 당첨 등수는 일치하는 번호의 개수에 따라 1등부터 5등까지 결정됩니다.

## 🎯 주요 기능

### 로또 구매
- 1,000원 단위로 로또 구입 금액을 입력받습니다
- 구입 금액에 해당하는 만큼 로또를 자동으로 발행합니다
- 발행된 로또 번호는 오름차순으로 정렬되어 출력됩니다

### 당첨 확인
- 당첨 번호 6개와 보너스 번호 1개를 입력받습니다
- 구매한 로또와 당첨 번호를 비교하여 등수를 판정합니다
- 등수별 당첨 개수와 총 수익률을 계산하여 출력합니다

### 당첨 기준 및 상금
| 등수 | 당첨 조건 | 당첨금 |
|-----|---------|-------|
| 1등 | 6개 번호 일치 | 2,000,000,000원 |
| 2등 | 5개 번호 + 보너스 번호 일치 | 30,000,000원 |
| 3등 | 5개 번호 일치 | 1,500,000원 |
| 4등 | 4개 번호 일치 | 50,000원 |
| 5등 | 3개 번호 일치 | 5,000원 |

## 📋 기능 목록

### 1. 로또 구매 기능
- [x] 구입 금액을 입력받는다
- [x] 구입 금액에 따라 로또를 발행한다 (1,000원당 1개)
- [x] 발행된 로또 수량과 번호를 출력한다
- [x] 로또 번호는 1부터 45까지의 숫자 중 중복되지 않는 6개로 구성한다
- [x] 로또 번호는 오름차순으로 정렬하여 출력한다

#### 예외 상황
- [x] 구입 금액이 숫자가 아닌 경우 예외 발생
- [x] 구입 금액이 1,000원 미만인 경우 예외 발생
- [x] 구입 금액이 1,000원 단위가 아닌 경우 예외 발생
- [x] 구입 금액이 빈 값이거나 공백만 입력된 경우 예외 발생
- [x] 구입 금액이 Integer 범위를 초과하는 경우 예외 발생

### 2. 당첨 번호 입력 기능
- [x] 당첨 번호 6개를 입력받는다
- [x] 당첨 번호는 쉼표(,)를 기준으로 구분한다
- [x] 보너스 번호 1개를 입력받는다

#### 예외 상황
- [x] 당첨 번호가 6개가 아닌 경우 예외 발생
- [x] 당첨 번호에 숫자가 아닌 값이 포함된 경우 예외 발생
- [x] 당첨 번호에 중복된 숫자가 있는 경우 예외 발생
- [x] 당첨 번호가 1~45 범위를 벗어나는 경우 예외 발생
- [x] 당첨 번호 입력 형식이 올바르지 않은 경우 예외 발생 (쉼표 누락, 잘못된 구분자 등)
- [x] 당첨 번호가 빈 값인 경우 예외 발생
- [x] 보너스 번호가 숫자가 아닌 경우 예외 발생
- [x] 보너스 번호가 1~45 범위를 벗어나는 경우 예외 발생
- [x] 보너스 번호가 당첨 번호와 중복되는 경우 예외 발생
- [x] 보너스 번호가 빈 값인 경우 예외 발생

### 3. 당첨 통계 기능
- [x] 구매한 로또와 당첨 번호를 비교하여 등수를 계산한다
- [x] 일치하는 번호의 개수에 따라 1등부터 5등까지 판정한다
- [x] 5개 일치 시 보너스 번호 일치 여부에 따라 2등과 3등을 구분한다
- [x] 등수별 당첨 개수를 집계한다
- [x] 총 수익률을 계산한다 (당첨금 합계 / 구입 금액 × 100)
- [x] 수익률은 소수점 둘째 자리에서 반올림하여 표시한다

### 4. 예외 처리
- [x] 잘못된 값 입력 시 `[ERROR]`로 시작하는 에러 메시지를 출력한다
- [x] 예외 발생 시 해당 입력 단계부터 다시 입력받는다
- [x] `IllegalArgumentException`을 사용하여 명확한 예외를 처리한다

## 🏗️ 구조 및 설계

### 아키텍처
- **MVC 패턴**을 적용하여 책임을 명확하게 분리했습니다
  - **Controller**: 게임 흐름 제어 및 예외 처리
  - **Service**: 비즈니스 로직 (로또 발행, 당첨 계산)
  - **View**: 사용자 입력 및 출력
  - **Domain**: 핵심 도메인 로직 (로또, 등수, 당첨 결과)
  - **Util**: 검증 로직

### 주요 클래스
- `Application`: 애플리케이션 실행 시작점
- `LottoGameController`: 게임 전체 흐름 제어
- `LottoService`: 로또 발행 및 당첨 결과 계산
- `Lotto`: 로또 번호를 관리하는 도메인 객체
- `Rank`: 당첨 등수를 관리하는 Enum
- `LottoResult`: 당첨 통계 및 수익률 계산
- `Validator`: 사용자 입력 검증
- `InputView`: 사용자 입력 처리
- `OutputView`: 결과 출력 처리

## 🧪 테스트
TDD(테스트 주도 개발)를 기반으로 도메인 로직과 예외 처리를 구현했으며, 단위 테스트와 통합 테스트를 분리하여 각 계층의 책임을 검증했습니다.

### 1. 단위 테스트 (Unit Test)
**[Domain]**
- `LottoTest`: 로또 번호 개수, 중복, 범위 검증 및 정렬, 번호 포함/일치 개수 계산 로직을 검증합니다.
- `RankTest`: 일치 개수/보너스 여부에 따른 `Enum` 판별 로직과 상금 메시지 포맷팅을 검증합니다.
- `LottoResultTest`: 당첨 통계(`Map`) 초기화, `add` 기능 및 수익률 계산(반올림 포함) 로직을 검증합니다.

**[Service/Util]**
- `LottoServiceTest`: 로또 발행 개수(`issueLottos`) 및 통계 계산(`calculateResults`) 로직을 검증합니다.
- `ValidatorTest`: 모든 사용자 입력값(구매 금액, 당첨 번호, 보너스 번호)에 대한 엣지 케이스를 TDD로 검증합니다.
  - 빈 값(`""`), `null`, 공백(`" "`) 입력
  - 숫자 형식(`1000j`), 잘못된 구분자(`1.2.3`), 쉼표 형식(`1,2,,`) 오류
  - 숫자 범위 초과 (`Integer Overflow`)
  - 비즈니스 로직(1000원 단위, 1~45 범위, 중복) 위반

### 2. 통합 테스트 (Integration Test)
- `ApplicationTest`: `NsTest`를 활용하여 실제 애플리케이션 실행과 동일한 환경에서 E2E 테스트를 진행합니다.
  - **정상 흐름 검증:** `기능_테스트`를 통해 정상적인 구매부터 당첨 통계 출력까지의 전체 흐름을 검증합니다.
  - **예외 및 재입력 검증:** `예외_테스트_구입금액`, `예외_테스트_당첨번호`, `예외_테스트_보너스번호`를 통해, TDD로 검증된 모든 엣지 케이스 예외 발생 시 `[ERROR]` 메시지를 출력하고, `Controller`가 해당 입력부터 **정확하게 다시 입력받는지(복구되는지)** 검증합니다.

### 도전했던 부분
- MVC 패턴을 적용하여 책임을 명확하게 분리하는 과정
- 예외 발생 시 해당 입력 단계부터 재입력받는 로직 구현
- 2등과 3등을 구분하기 위한 보너스 번호 처리 로직
- 수익률 계산 시 소수점 반올림 처리
